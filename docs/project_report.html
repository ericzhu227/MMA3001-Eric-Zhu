1. Engineering problem and aims

Indoor CO₂ concentration is a practical proxy for whether ventilation is keeping up with occupancy and other indoor sources. A short-term forecast can provide an early warning before concentration becomes excessive, supporting inspection or ventilation-control decisions.

The project asks: how accurately can the selected MSI environmental sensor predict CO₂ concentration approximately 20 minutes ahead? The intended use is decision support for ventilation monitoring, not automatic control or a claim about health thresholds. The scope is one sensor and one contiguous period with measured targets; it does not establish performance across rooms, seasons or buildings.

2. Dataset and inputs/outputs

The repository contains an environmental CSV with JSON-packed readings, an occupancy CSV and a sensor-location workbook. The implemented forecasting dataset uses sensor 6012002000869, from 2024-02-29 06:04:56 UTC to 2024-06-13 17:45:44 UTC. CO₂ is measured in ppm; temperature is in °C; humidity uses the source sensor unit. The target is the measured CO₂ value about 20 minutes after the forecast issue time.

Inputs are current and historical CO₂, temperature, humidity and a CO₂ change-rate feature. Occupancy is excluded because the available occupancy-to-room mapping is marked incorrect or unresolved; using it could associate people counts with the wrong environmental sensor and create misleading features.

3. Data cleaning and exploration

The workflow extracts measurement times from the environmental JSON rather than database creation times. Exact duplicate measurements are removed, while conflicting values for the same sensor/time/variable are excluded rather than arbitrarily selecting one. Non-finite values and non-positive CO₂ are excluded; other unusual values remain visible for inspection. No interpolation or target filling is used.

A gap greater than 30 minutes starts a new contiguous period. This is long enough to distinguish an outage from the approximately 10-minute sampling pattern while avoiding invented continuity across a substantial break. The selected sensor-period is the longest by timestamp coverage, chosen before modelling and without using forecast errors. The notebook’s coverage audit and plots document the sampling intervals and gaps.

4. Feature construction

The model uses the current CO₂ value, CO₂ values approximately 10 and 20 minutes earlier, temperature and humidity, and a CO₂ rate feature. Historical values are obtained by backward matching: for an issue time, only measurements at or before that time are eligible, with a limited staleness tolerance. This prevents a later reading from leaking into an earlier feature.

Rates are calculated from the actual elapsed time between the matched measurements, rather than assuming every interval is exactly 10 or 20 minutes. The target is also matched to an observed measurement within the declared 20-minute tolerance, so the evaluation reflects available observations rather than interpolated ground truth.

5. Validation design

Forecast issue times are split chronologically into approximately 60% training, 20% validation and 20% final test. Random splitting would allow nearby records from the future to appear in training and would make the evaluation look easier than deployment on genuinely later data.

Boundary purging removes earlier examples whose future target reaches into the next split. The final test period remains untouched during feature-set and model selection. Learned transformations, if used, must be fitted on training data only.

6. Model development

Persistence predicts that future CO₂ will equal the current CO₂ value, giving a transparent operational baseline. Ordinary least squares estimates a weighted combination of the selected features. Decision trees partition the feature space into regions and predict the average target in each leaf; depths 2, 4, 6, 8 and unlimited, with minimum leaf sizes 5, 20 and 50, were compared.

Four feature sets compare CO₂ history, environmental variables, and 10- or 20-minute rates. Validation MAE selects the configuration, with persistence included as a candidate, before the frozen selected model is scored on the final test.

8. Sensitivity and performance

The selected model is only modestly better than persistence, which indicates that recent CO₂ history carries most of the predictive signal. Adding temperature, humidity and rate features provides a small validation improvement. Synthetic input noise increases validation MAE from 10.2028 ppm at 0 ppm noise to 12.0657 ppm at 10 ppm noise, showing sensitivity to measurement quality.

9. Engineering discussion and limitations

The results support using the model as a monitoring aid: it can improve average 20-minute forecasts over persistence for this sensor-period, especially during rising CO₂. It should not be used as the sole basis for ventilation action because the study does not calibrate sensor accuracy, infer causal ventilation effects or evaluate health thresholds.

Errors are expected around abrupt changes, unusual operating conditions and periods unlike the training data. Important limitations are the single sensor, one contiguous period, unresolved room mapping, measured-target tolerance, synthetic rather than calibrated noise, and selection based on one validation period. Decision trees also cannot extrapolate beyond the target values represented in their leaves.

10. Conclusion

For the selected MSI sensor and 20-minute measured horizon, the linear model using CO₂ history, environmental history and the 20-minute rate is the strongest tested approach. It reduces final-test MAE from 8.6906 ppm for persistence to 7.8328 ppm and RMSE from 10.9208 ppm to 9.7250 ppm. The improvement is useful but moderate, so the answer is that short-term forecasting is feasible as supplementary ventilation monitoring rather than a standalone control system.

Realistic improvements include resolving the room mapping, evaluating multiple sensors and seasons, collecting higher-frequency measurements, calibrating uncertainty against sensor specifications, adding validated occupancy or calendar features, and using rolling-origin evaluation across more periods.
